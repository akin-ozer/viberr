# UC-15 — Granted skill loads natively (R18-5); decoy/ungranted skills do NOT

## Purpose

Proves **ruling 51 / R18-5** and its fences, live:

1. A granted skill reaches a Claude run through the SDK's NATIVE `skills: [...]` channel —
   mounted as `<workspace>/.claude/skills/<name>` (`mountGrantedSkills`,
   `app/server/runtimes/skill-mount.server.ts:145-188`), announced by metadata, body loaded
   only on Skill invocation (progressive disclosure; `buildSpecialistPersona` deliberately
   does NOT inject a mounted skill's body, `specialist-run.server.ts:1233-1253`).
2. The `skills` allow-list is the fence: an UNGRANTED skill (the decoy) and the SDK's ~16
   compiled-in bundled skills are rejected at the tool boundary
   (`claude-runtime.server.ts:594-608`; `Skill` leaves the denylist ONLY because the filter
   replaces it, `:657-665`).
3. **Ruling 49 / R18-3** — the repo's own `.claude` catalog is stripped git-invisibly
   (`stripUngovernedRepoCatalog`, `skill-mount.server.ts:61-88`; skip-worktree + rmSync),
   and the mount is excluded from delivery via `.git/info/exclude`
   (`excludeCatalogFromDelivery`, `:210-236`).
4. Mounted `SKILL.md` frontmatter is REWRITTEN to exactly `{name, description}`
   (`:282-291`) — store skills can never smuggle `allowed-tools`/`model` policy.

## Failure signatures (findings)

- `$WS/.claude/skills/` absent while reply (2) still quotes the canary → the mount was
  skipped and the PROMPT-TEXT fallback fired on a healthy plain checkout → **NEW** against
  `mountGrantedSkills`/`isPlainGitCheckout` (`skill-mount.server.ts:192-198`) — the
  fallback is legitimate only for Codex/no-checkout/bad-name cases.
- Decoy invocable or its sentinel quoted anywhere → **NEW HIGH**: allow-list breach
  (ungranted resource reached a run — the R18-5 fence failed).
- A bundled skill (pdf/docx/…) invocable → **NEW HIGH**: the `skills` filter is not
  containing the SDK's compiled-in set (`claude-runtime.server.ts:594-608`).
- Mounted `SKILL.md` frontmatter carries keys beyond `name`/`description` (for example
  `allowed-tools`) → **NEW HIGH**: normalization broken (`skill-mount.server.ts:282-291`).
- `git -C "$WS" status` shows `.claude` deletions/additions → **NEW HIGH**: R18-3
  skip-worktree/exclude regression — a delivery would ship catalog edits into the PR.
- Skill list shows the full body ALREADY in the system prompt (reply 5 = "pre-loaded")
  while the mount dir exists → double-feed — **NEW** against the `nativeSkills` seam
  (`specialist-run.server.ts:1233-1236`).
- A second run stripping the mount mid-run → **F19-15** (already filed; record the repro,
  don't re-file).
- Reply includes "Attached resources that did NOT reach this run" naming the skill → grant
  string vs store folder mismatch (slugify) — misconfiguration unless names match, then
  **NEW** (resolver/containment refusal on a healthy store entry).
