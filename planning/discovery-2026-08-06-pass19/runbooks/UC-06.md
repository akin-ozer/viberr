# UC-06 — PR closed externally on GitHub → divergence surfaced + operator recovery packet

## Purpose

Proves **ruling 17** (out-of-band PR transitions fire a `pr-diverged` operator trigger; a
closed PR opens ONE recovery packet: rework / `archive_task` / `archive_task`+`deleteBranch`),
**R16-3** (a closed unmerged PR is a terminal GitHub fact: named FIRST in refusal copy,
Force-accept **withdrawn**, not disabled), **FR32/NFR14** (branch/PR status surfaced), and the
divergence-healing counter-event (reopen lifts the block). Mechanisms under test:

- `reconcileTask` (`app/server/github/github-reconciler.server.ts:161-624`):
  `prJustClosed && !taskTerminal` → `closedButActive` → Policy-engine `note`
  "**Divergence:** PR #N was closed on GitHub without merging, but KEY is still active.
  Decide whether to rework and reopen, or archive the task." (:433), withdrawal of now-moot
  `transition` **and** `accept_completion` recommendations (:444-456), watcher notification
  "PR #N closed on GitHub — KEY needs a decision" (:537), and `autoInvokeOperator(...,
  "pr-diverged")` fire-and-forget (:560-571).
- Operator `pr-diverged` turn, `prState === "closed"` branch
  (`app/server/runtimes/operator-run.server.ts:2207-2216`): open ONE `input` packet whose
  options are a `custom` REWORK, `archive_task`, and `archive_task` with `deleteBranch: true`;
  exactly one `rec: true`; body must say reopening on GitHub is also valid.
- Acceptance refusal: `closedPrBlockedReason` (`app/schemas/task-file.schema.ts:617`),
  `acceptanceTerminallyBlocked` (`app/server/tasks/task-actions.server.ts:4778-4780`).
- Review queue: `closed` jumps every process gate in the subline
  (`app/features/review/review-helpers.ts:72`).
- Healing: `prJustReopened` (:415-420) → "PR #N was reopened on GitHub — … the closed-PR
  block is lifted." + operator re-invoked to withdraw the moot packet (:2224-2227).

## Steps

1. **Close the PR on GitHub, out-of-band** [API]:
   `gh pr close $PRN -R akin-ozer/viberr` (do **NOT** pass `--delete-branch`).
   Immediate: `gh pr view $PRN … --json state` → `CLOSED`; Viberr still shows `review`
   (nothing has reconciled yet).
2. **Reconcile** [API]: `post http://localhost:5173/projects/viberr-core/github
   --data-urlencode intent=reconcile` → `{ok:true}` with a toast naming reconciled counts.
   Do not fire it twice concurrently (F19-19: overlapping passes duplicate the note).
3. **Assert the deterministic divergence surface** [API] — read task.md:
   - `pr.state: closed` (same PR number — the owned link was kept honest, not dropped).
   - Newest timeline `note` by the Policy engine, exact text:
     "**Divergence:** PR #$PRN was closed on GitHub without merging, but $KEY is still
     active. Decide whether to rework and reopen, or archive the task."
     (+ a "The now-moot … withdrawn" suffix iff recommendations existed).
   - `recommendations`: any `transition` or `accept_completion` entries present before step
     2 are GONE (others survive).
4. **Assert the notification** [API]: notifications query → a row titled
   "PR #$PRN closed on GitHub — $KEY needs a decision". [UI] bell popover shows it.
5. **Wait for the operator recovery turn** (auto-fired, trigger `pr-diverged`; agentic —
   1–3 min). [API] poll `agent_runs` for a new `operator` row → `finished`. Then task.md:
   - ONE `## Packet`, `type: input`, from `operator`, options containing (kinds, never
     titles): one `custom` (rework), one `archive_task`, one `archive_task` with
     `deleteBranch: true`; exactly one `rec: true`; body mentions that reopening the PR on
     GitHub is also a valid path.
   - If VC-2-style packet variance occurs (model wording differs), PASS on option KINDS.
6. **Acceptance is refused, terminally** —
   - [API] `post .../tasks/$KEY --data-urlencode intent=accept-completion` → error response
     whose text names the closed PR FIRST (R16-3), from `closedPrBlockedReason`.
   - [UI] task page: no Accept control; **Force-accept is absent entirely** (withdrawn, not
     disabled — `acceptanceTerminallyBlocked`).
   - [UI] review queue row subline reads exactly: "PR #$PRN was closed on GitHub without
     merging — rework and reopen it, or archive the task." (jumps every process gate).
   - [UI] board card / task rail: closed-PR pill renders `risk` tone (ruling 12).
7. **Healing probe (optional but recommended)** [API]:
   `gh pr reopen $PRN -R akin-ozer/viberr`, reconcile again. Expect:
   - timeline note "**Note:** PR #$PRN was reopened on GitHub — $KEY's review is live again
     and the closed-PR block is lifted."
   - notification "PR #$PRN live again on GitHub — $KEY resumes".
   - operator re-invoked (`pr-diverged`, `review` branch): the recovery packet is RESOLVED
     as moot (agentic; check `## Packet` is gone or marked resolved on the timeline).
   Then close it again (`gh pr close $PRN …`) + reconcile once more if you want to finish
   via the packet in Cleanup.

## Failure signatures (findings)

- Reconcile does not detect the close (pr stays `review` after step 2) → **NEW HIGH**
  (R8-6 divergence dead).
- Divergence note or notification fires again on every subsequent reconcile (no
  transition-edge dedup) → **NEW MED**; if caused by two overlapping passes, that is
  **F19-19 (filed)** — record the repro, do not re-file.
- Moot `transition`/`accept_completion` recommendations survive step 2 → **NEW MED**
  (withdrawal contract, reconciler :444-456).
- No operator run fires (and an operator IS deployed) → **NEW HIGH** (`autoInvokeOperator`
  pr-diverged wiring).
- Recovery packet missing `archive_task`+`deleteBranch`, or a SECOND packet replaces an
  open one → **NEW MED** (ruling 17 / B3).
- Force-accept still rendered (even disabled) while PR closed → **NEW HIGH** (R16-3).
- Accept succeeds while PR closed → **NEW CRITICAL** (`closedPrBlockedReason` bypassed —
  same family as the pass-16 three-writers bug).
- Queue subline shows a process gate ("no approving verdict…") instead of the closed-PR
  fact → **NEW MED** (R16-3 regression, `review-helpers.ts:72`).
