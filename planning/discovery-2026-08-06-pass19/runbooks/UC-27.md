# UC-27 — Interrupt the operator mid-run; manual re-run recovers cleanly

## Purpose

Proves run-lifecycle **ruling 11** (`queued|running|finished|error|interrupted`) and the
operator single-flight lease's behavior across a human interruption:

1. `interruptRun` (`app/server/runtimes/run-service.server.ts:878-952`): RBAC
   `run-agents` (admin|maintainer), stamps `interruptedBy`, the adapter's onExit →
   sink.finalize writes `state: interrupted`, audits `runtime.run.interrupted`,
   idempotent (`already-terminal` on a second call, which returns BEFORE the audit — so
   exactly one audit row).
2. Interruption is a **terminal** state that fires the run's completion callback
   (`fireIfAlreadyTerminal` treats finished/error/interrupted alike, :112-134), so the
   Claude operator path's chained completion runs — and because
   `finished.state !== "error"`, it must **NOT** escalate a failure packet
   (`startRealOperatorRun`, `operator-run.server.ts:1750-1773`;
   `escalateFailedOperatorRun` is error-only). It releases the lease
   (`releaseOperatorLease`) and settles `waiting: agent → human`
   (`settleWaitingAfterOperator`, :590-619).
3. The stranded-resume backstop must NOT fire after an interrupt —
   `maybeResumeStrandedOperator` requires the run row `state === "finished"` (:472-483).
4. A **manual re-run** (`intent=run-operator`, trigger `manual`) acquires a FRESH lease —
   the toast says "Operator running", never "Operator queued" — and completes a full turn,
   proving no lease leak and no residue from the interrupted turn.

## Failure signatures (findings)

- Step 9 toast `Operator queued · runs when the current run finishes …` or the re-run
  never starts → **NEW HIGH**: lease not released on interrupt (AO-2/B5 family —
  the completion chain skipped `releaseOperatorLease` for `interrupted`).
- Step 5 shows an "Operator run failed — pick a recovery path" packet → **NEW MED**:
  a human-initiated stop escalated as a failure (`escalateFailedOperatorRun` must be
  error-only) — alarm-fatigue class, "contained seriousness" violated.
- Step 4 row stays `running`/`queued` after the interrupt → **NEW HIGH**: the adapter's
  `handle.interrupt()` → onExit → finalize chain broke; the row would only heal at boot
  (`finalizeOrphanedRuns`), and the completion callback (lease release) never fires.
- Step 6 `waiting` stuck on `agent` → **NEW MED**: `settleWaitingAfterOperator` failed —
  the board lies "working" on an idle task until the next mutation reprojects.
- Step 7 a new operator run self-starts after the interrupt → **NEW MED**:
  `maybeResumeStrandedOperator` fired on a non-`finished` run (its `state === "finished"`
  guard exists precisely to keep an errored/interrupted drive from looping).
- `interrupted_by` NULL while the audit row names Arda → **NEW LOW**: the
  pre-finalize `patchRun` stamp raced/lost (run-service.server.ts:917-919).
- Step 8 produces a SECOND `runtime.run.interrupted` audit row → **NEW LOW**: the
  already-terminal early-return moved below the audit write.
- Step 10 re-run errors with residue referencing the interrupted turn → **NEW**: record
  verbatim; the manual trigger must start from canonical task state (FR22/NFR12).
