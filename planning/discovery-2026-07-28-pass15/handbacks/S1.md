## H1 — B-WF4 leftover: `schedule.server.ts` resolves the terminal stage positionally

File: `app/server/tasks/schedule.server.ts:77-81`

```ts
/** The project's final (terminal/Done) stage id, or null. */
function terminalStageId(db: DatabaseSync, projectSlug: string): string | null {
  const stages = getProject(db, projectSlug)?.stages ?? [];
  return stages[stages.length - 1]?.id ?? null;
}
```

Patch: resolve structurally like every other consumer now does
(`operatorAcceptCompletion` and `task-actions` both go through
`resolveStageRoles`):

```ts
import { resolveStageRoles } from "~/shared/workflow/stage-roles";

function terminalStageId(db: DatabaseSync, projectSlug: string): string | null {
  const project = getProject(db, projectSlug);
  if (!project) return null;
  return (
    resolveStageRoles(project.stages, project.workflow ?? []).terminalId ??
    project.stages[project.stages.length - 1]?.id ??
    null
  );
}
```

Note: verify `ProjectRecord` (board-query projection) carries `workflow`; if it
does not, read the project FILE the way task-actions does, or extend the
projection. They agree only while terminal = last — the same drift class
F15-17 came from.

## H2 — F15-02: "Update status" gives zero feedback + freshness never flips

Files: `app/features/github/github-actions.server.ts` (`runReconcile`, :36-55),
`app/features/github/github-copy.ts` (`reconcileToast`).

Root cause of the live 14ms no-op: `reconcileProject`
(github-reconciler.server.ts:538-557) returns `{status: gh.status, results: []}`
when the GitHub context is degraded, and reconciles ZERO tasks when no task has
a branch — in both cases no `github.reconcile` provenance row is written, so
`latestProjectReconcileAt` stays null and the "Not yet synced" badge never
flips, while the button's toast reads like success.

Patch `runReconcile` to name both cases honestly:

```ts
const summary = await reconcileProject(db, projectSlug, actor, ctx);
if (summary.status !== "reconciled" && summary.results.length === 0) {
  // Degraded context (no repo / no credential / auth) — nothing was scanned.
  return {
    ok: false,
    toast: `Nothing was synced — ${copyForContextFailure(summary.status)}`,
    result: summary.status,
  };
}
if (summary.results.length === 0) {
  return {
    ok: true,
    toast: "Nothing to sync yet — no task has a delivery branch.",
    result: "no_branched_tasks",
  };
}
```

…and (optional, fixes the badge half): have a successful `reconcileProject`
pass with zero branched tasks still record a project-level provenance heartbeat
so `reconcile.at` reflects "we checked", or change the github-view freshness
copy to distinguish "never checked" from "nothing to check". The UI half
(spinner/pending state on the button while `reconcileFetcher` is submitting) is
in `app/features/github/github-view.tsx:485-496` — it already disables on busy;
add a "Checking GitHub…" label so the 14ms/slow cases are both visible.
