# UC-23 — Hand-edit task.md in the store → reconciliation (watcher + Re-scan, FR10/FR36)

## Purpose

Proves the file-native store contract:

- **FR10** — the store is inspectable AND editable outside the app; direct edits reconcile
  into the projections. Live mechanism: the chokidar watcher
  (`app/server/files/file-watch.service.server.ts`; 250 ms debounce, runs in dev AND prod,
  watches `projects/**/{project.md,task.md}` only) reprojects a saved edit via
  `rebuildPath` (`app/server/projections/rebuilder.server.ts:584`).
- **FR36** — manual re-scan: board "Re-scan" (`intent=rescan` on
  `/projects/viberr-core/board`, gate `rescan-project`, maintainer+) reconciles ONE
  project on demand; the home store strip's whole-store variant is org-admin-only.
  Audited as `projection.rescan`.
- **Tolerance contract / NFR13** — a malformed hand-edit yields diagnostics + a readiness
  downgrade, never a crash, a dropped task, or an uncommanded rewrite of the file
  (`stored_readiness` NULL, derived readiness from
  `app/server/interpretation/readiness-policy.server.ts`).

### Note on scope

The watcher makes Re-scan redundant for edits made while the server is up; the case
Re-scan (plus the boot rescan) exists for is offline drift — edits landing while the
process is down. A full stop/edit/start cycle is out of scope here (restart churn on the
shared dev server); if the pass wants it: stop the dev server, edit the title again,
start it, and verify the boot rescan projects the change without any Re-scan click.

## Failure signatures (findings)

- Edit never appears (search + UI stale >10 s) with `watcher: true` → **NEW HIGH** watcher
  reconcile defect (FR10). With `watcher: false` → **NEW** watcher-lifecycle finding
  (health honesty is E8's contract).
- Malformed readiness crashes a route, 500s, or drops VC-2 from the board → **NEW HIGH**
  tolerance-contract violation (NFR13: "malformed input yields diagnostics + a readiness
  downgrade, never a crash or silent drop").
- Malformed value silently renders as a normal healthy state (no downgrade, no
  diagnostic) → **NEW** state-semantics finding (G2 family).
- The app REWRITES the hand-edited file uncommanded (bytes differ beyond your edit;
  e.g. it normalizes `banana` away) → **NEW HIGH** files-are-truth violation.
- Re-scan changes task content or bumps every task's projections on an unchanged store
  in a way that fires SSE churn → **NEW** idempotency finding (NFR16 family).
- Re-scan allowed for EK / whole-store rescan allowed for a non-org-admin → **NEW** RBAC
  finding.
- Board/search reflect the edit but the open packet or timeline was LOST by the rebuild →
  **NEW CRITICAL** (reconciliation corrupted state, NFR13).
