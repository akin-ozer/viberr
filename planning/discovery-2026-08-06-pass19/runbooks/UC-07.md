# UC-07 — PR merged externally via `gh` → owned link kept honest, divergence surfaced, acceptance closes the loop (DG-1)

## Purpose

Proves the **merged-out-of-band** half of ruling 17 / R8-6 (surface, never auto-advance),
**R15-15/R16-1 owned-link honesty** (the SAME PR number's live facts update the task; an
external merge is never treated as a foreign PR), **DG-1** (a dead — merged/closed — cached
PR is never reused by a later delivery; `pr-open.server.ts:180-207`), and the
recommendation-withdrawal asymmetry (a merge withdraws `transition` recs but an
`accept_completion` rec SURVIVES — accepting is exactly right). Mechanisms under test:

- `reconcileTask` (`app/server/github/github-reconciler.server.ts`):
  `sameAsCached` (:288) keeps the owned link and flips its state; `prJustMerged &&
  !taskTerminal` → `mergedButNotDone` (:403-408) → Policy-engine note
  "**Divergence:** PR #N was merged on GitHub, but KEY hasn't been accepted through Viberr —
  its stage is unchanged. Accept the completion (or move it to Done) so the task reflects
  the merge." (:431), withdrawal of `transition` recs ONLY (:437-450), notification
  "PR #N merged on GitHub — accept KEY" (:535), `autoInvokeOperator(..., "pr-diverged")`.
- Operator `pr-diverged` turn, `merged` branch (`operator-run.server.ts:2218-2221`):
  `accept_completion` per policy — Viberr Core's operator holds
  `completion-for-acceptance: recommend`, so the expected artifact is an
  `accept_completion` RECOMMENDATION card, not a direct close.
- Human acceptance of an already-merged PR (`acceptCompletion` / `intent=accept-completion`):
  the `alreadyMerged` branch records "Human acceptance recorded. Task transitioned to
  **Done**; the review PR had already been merged on GitHub." — no second merge call.
- Sync state: `deriveSyncState({prMerged: true, …})` → `merged` pill
  (`branch-sync.server.ts`).

## Steps

1. **Merge the PR on GitHub, out-of-band** [API]:
   `gh pr merge $PRN -R akin-ozer/viberr --merge` (no `--delete-branch` — external merges
   leave the branch; Viberr's own R15-6 cleanup only runs on Viberr-driven merges).
   Immediate: `gh pr view $PRN … --json state,mergedAt` → `MERGED`; Viberr still says
   `review` until reconcile.
2. **Reconcile** [API]: `post .../github --data-urlencode intent=reconcile`. Single-fire
   (F19-19 caveat: never two overlapping passes).
3. **Assert owned-link honesty + divergence** [API] — read task.md:
   - `pr.number` UNCHANGED = $PRN, `pr.state: merged` — the external merge updated the
     owned link (`sameAsCached`); it was NOT demoted to `github.unownedPr`, and NO
     collision note appeared.
   - `mergeable`/`review` keys DROPPED from `pr` (a settled PR carries neither —
     P13-D-28/P14-LV-07).
   - Newest timeline note (Policy engine), exact text: "**Divergence:** PR #$PRN was merged
     on GitHub, but $KEY hasn't been accepted through Viberr — its stage is unchanged.
     Accept the completion (or move it to Done) so the task reflects the merge."
   - Recommendation asymmetry: any `transition` rec present before step 2 is withdrawn; an
     `accept_completion` rec (if the operator had left one) SURVIVES.
4. **Notification** [API]: a row titled "PR #$PRN merged on GitHub — accept $KEY".
   [UI] bell shows it.
5. **Operator turn** (auto, trigger `pr-diverged`, agentic — 1–3 min): [API] new
   `operator` row in `agent_runs` reaches `finished`; task.md gains an
   `accept_completion` **recommendation** (operator's `completion-for-acceptance` is
   `recommend`) — NOT a stage change, NOT a packet (the merged branch instruction says
   accept, `operator-run.server.ts:2218-2221`). No agent re-prompted.
6. **Surfaces** [UI]:
   - Board card / task rail: PR pill `merged` (done-tone, ruling 12); branch sync pill
     `merged` (precedence merged > behind > synced).
   - Review queue subline: "PR #$PRN is merged on GitHub — accept the completion to close
     the task." (merged does NOT jump a real process gate — here there is none).
7. **Close the loop as a human** — either [UI] task page → Accept completion (R15-1
   confirm dialog appears; "Merges" row shows PR #$PRN · merged) → confirm; or [API]
   `post .../tasks/$KEY --data-urlencode intent=accept-completion`. Expect toast
   "Completion accepted · $KEY moved to Done". Read task.md:
   - `stage: done`, `readiness: ready`, `waiting: none`, `recommendations: []` (acceptance
     consumes all).
   - Completion event text: "Human acceptance recorded. Task transitioned to **Done**; the
     review PR had already been merged on GitHub." (the `alreadyMerged` branch — no second
     merge attempt, no `github.pr.merged` audit row for this step).
8. **DG-1 probe (optional, recommended)** — a dead cached PR is never reused: put one more
   commit on the workspace branch
   (`cd $WS/viberr && printf 'rework\n' >> qa/smoke/pass19-uc07-probe.md && git commit -am "[$KEY] rework probe"`),
   then `post .../tasks/$KEY --data-urlencode intent=deliver-review`. Expect a **FRESH** PR
   number (`created: true` toast "Delivered · opened review PR #<N2>", N2 ≠ $PRN) — the
   merged #$PRN was skipped by `cachedPrIsTerminal` (`pr-open.server.ts:180-207`), never
   "reused" into a dead review. (This mirrors the live VC-4 history: closed #149 → fresh
   #150.) Note: the task is at `done` now; delivery is stage-independent (R15-2). Close the
   fresh PR afterwards (`gh pr close N2 …`) — it is probe residue.

## Failure signatures (findings)

- The externally merged PR is treated as FOREIGN (`github.unownedPr` set, collision note,
  `pr` dropped) → **NEW HIGH** — owned-link honesty regression (R15-15/R16-1; the exact H8
  class the two-rule split exists to prevent).
- Task auto-advances to Done on reconcile (stage changed with no human accept) → **NEW
  CRITICAL** (R8-6 "never auto-advance"; files-canonical violation).
- `accept_completion` rec withdrawn on merge (or `transition` rec kept) → **NEW MED**
  (withdrawal asymmetry, reconciler :437-450).
- Operator DIRECTLY accepts/transitions under `completion-for-acceptance: recommend` →
  **NEW HIGH** (capability-mode bypass).
- Step 7 attempts a second GitHub merge (a `github.pr.merged` audit row / 405 surfaced) →
  **NEW MED** (`alreadyMerged` branch regression).
- Step 8 reuses merged #$PRN → **NEW HIGH** = DG-1 regression ("merge pending" dead-end,
  pass-12 class).
- Divergence note/notification duplicated by overlapping reconciles → **F19-19 (filed)**;
  record repro only.
- "Synced Nm ago" freshness cue stuck despite 5-min poller passes → **F19-22 (filed)**;
  incidental here.
