This plan turns the pass-10 canon, implementation map, findings, executed evidence, and current source/test contracts into independently dispatchable cases. It does not authorize any new live provider run, GitHub mutation, product-code change, or canonical-data change.

## Stop condition: a project is not a sandbox

**A fresh Viberr project is NOT operating-system isolation.** A new project only separates canonical records and UI navigation. Its Claude and Codex specialists still execute as the same OS user as the Viberr server, can reach the shared data root and other workspaces, and inherit or locate provider/runtime material. Claude also receives the full server environment; Codex specialists currently run with broad filesystem authority. The PXL project therefore reduced GitHub blast radius but did not contain an agent.

**No more real Claude or Codex agent runs are safe on the current deployment until process/container containment exists and the D-series canaries pass.** PXL-1 and PXL-2 are completed historical evidence, not templates to rerun. Browser reads, API reads, fake-SDK tests, simulated-runtime tests behind the explicit test gate, and temporary-data-root tests remain allowed.

## Entry gates

### Gate A — safe local/fake execution

- Revision and dirty-worktree inventory recorded; user-owned `.claude/launch.json` remains untouched.
- Real provider credentials and CLI-auth flags are absent from the test process; a guard test fails closed if any are present.
- Unique temporary data, DB, provider-home, and Git roots are confirmed; no test points at `./data`.
- SDK, GitHub, and network transports are fake or denied; simulation is reachable only through the paired test gate.
- Per-case actor/role, starting canonical file, and cleanup handler are defined.

### Gate B — historical evidence reconciliation

- PXL-1/PXL-2 task files, run rows, screenshots, and PR metadata are opened read-only.
- No task action, comment, session export, run/resume, PR action, or branch deletion is performed.

### Gate C — external GitHub mutation

- C-01 passes with an approved external account and exact repository identity.
- Human approval names every task key, branch, PR action, fixture path, and cleanup action.
- Baseline `main` SHA/tree and existing open artifacts are recorded; collision checks pass.
- Only inert `planning/audit-fixtures/<case>.md` content is allowed; product source/tests/config/dependencies are prohibited.
- No real agent process is used unless Gate D has already passed.

### Gate D — hostile containment

- Dedicated UID/container/VM; allowlisted workspace mount only; no host workspace, live data, Docker socket, SSH agent, or provider-home mount.
- Sentinel-only secrets and throwaway GitHub credentials/repository.
- Network allowlist plus CPU, memory, PID, disk, output, FD, and wall-time limits.
- Snapshot/rollback and an external kill switch tested before the first hostile prompt.

## Exit gates

- Every dispatched case has a result, oracle comparison, evidence pointer, and cleanup status; “not run” is explicit.
- No raw secret or real transcript was copied into logs, screenshots, fixtures, or planning files.
- S1 temporary processes are stopped and temporary roots removed; no watcher, timer, or fake run remains active.
- Any failed canonical invariant has a FINDINGS entry or implementation ticket; unresolved owner-policy behavior links to DECISIONS rather than being guessed.
- C-series exits only when the final remote inventory is reconciled, authorized fixtures are removed, task/PR states agree, and only explicitly approved test history/branches remain.
- The real-agent freeze is lifted only after all applicable D-series containment canaries pass under independent review. A clean PXL project, a clean Git tree, or successful cooperative agents is not sufficient evidence of isolation.
