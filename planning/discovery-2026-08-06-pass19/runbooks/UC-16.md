# UC-16 — Backend parity: the same work through a Claude and a Codex developer

## Purpose

Proves FR19 (execute approved profiles through Codex AND Claude Code backends) delivers the
SAME governed outcome, and pins the DELIBERATE asymmetries as disclosed-not-silent:

1. **Delivery is server-owned on both backends** (F-GH3): the agent commits locally, Viberr
   pushes the branch + opens the PR (`performDelivery` → `pushWorkspaceBranch` →
   `openTaskPr`); the PR author is the PAT owner, never the agent.
2. **F24 — one delivery identity**: commits on BOTH legs are authored
   `<profileId> <profileId>@viberr.local` (Claude via `GIT_AUTHOR_*` env; Codex via
   `shell_environment_policy.set`, `codex-runtime.server.ts:171-186` — the P13-RT-10 fix).
3. **Skill-carrier asymmetry (R18-5 / LV-13, deliberate)**: Claude mounts granted skills
   natively (`.claude/skills/` in the workspace); Codex has its skills channel severed and
   keeps prompt-text injection (`codex-runtime.server.ts:233-246`). KB is prompt text on
   BOTH.
4. **Transport asymmetry (G3/G4)**: Claude uses the in-process `viberr_agent` toolkit;
   Codex a structured outcome-envelope on its final reply (`useEnvelopeSchema`,
   `specialist-run.server.ts:1049-1052` — armed here because `ask-human` is granted).
5. Both runs produce the task's canonical evidence: timeline report, `workRevision`,
   branch + PR facts (NFR15 traceability).
