# UC-20 — "Completed — no changes" (R17-2) + PROOF of the F19-21 reachability boundary

## Purpose

Two goals in one runbook:

1. **R17-2 / ruling 43** — a verified no-diff task closes to Done as a first-class
   "**Completed — no changes required**" outcome: no PR, no merge, its own completion copy,
   reached through the normal acceptance ceremony (not force-accept, not archive).
2. **PROVE (or disprove) F19-21's boundary claim**: `fm.noChanges` is set ONLY inside
   `performDelivery` — `task-actions.server.ts:3482` (push status `no_commits`) and `:3621`
   (`openTaskPr` → `nothing_to_review`) — i.e. only after a **delivery attempt by an engaged
   deliverer with a workspace clone**. A verification-only task with no deliverer (VC-5's
   exact live shape) can never reach the R17-2 outcome, and even a hand-set `noChanges` flag
   cannot unblock it while a verdict-capable reviewer is engaged with no revision
   (`acceptanceBlockedReason`, `task-file.schema.ts:581`, fires before `verdictGateReason`,
   `task-actions.server.ts:4707`, the only reader of `noChanges`).

## Steps

### Arm A — boundary proofs on VC-5 (every probe expects a refusal)

1. **Probe 1 — the packet's own recommended option cannot execute.** [API]
   `intent=resolve-packet option=0` on VC-5 → expect **HTTP 409** with
   "No reviewed revision yet — nothing for the required reviewers to approve."
   (`acceptanceBlockedReason`: a required reviewer is engaged, `workRevision` is null; the
   throw precedes the write, so the packet stays OPEN — verify task.md unchanged.)
   This demonstrates F19-21's UX indictment: the packet's `rec: true` option is a dead end.
2. **Probe 2 — a hand-set flag does not unblock this shape.** [API]
   Insert `noChanges: true` into VC-5's frontmatter (one atomic save; e.g. add the line
   after `archived: false`). Wait ~2 s (watcher), repeat probe 1 → expect the **SAME 409**
   (gate order: `acceptanceBlockedReason` fires before `verdictGateReason`; `noChanges` is
   only consulted in verdictGateReason's has-revision/no-PR branch). **Revert the edit**
   (restore the exact previous file from your backup copy) and confirm the pill state
   returns. Keep a `cp task.md /tmp/…` style backup OUTSIDE the store before editing.
3. **Probe 3 — a delivery attempt with no deliverer cannot mint the flag.** [API]
   `intent=deliver-review` on VC-5 → expect **HTTP 409** "Delivery did not complete — VC-5
   has no workspace clone to deliver from…" (push status `no_workspace` → outcome
   `failed`, NOT `nothing_to_review`). Verify task.md: gained one `github` timeline event
   ("Delivery could not run" wording) and **no `noChanges` key**.
   → Probes 1–3 together CONFIRM F19-21: for VC-5's shape the R17-2 close is unreachable by
   any in-app path; the only exits remain force-accept / archive / bypassing ceremony.
